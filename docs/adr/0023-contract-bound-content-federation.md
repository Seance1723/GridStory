# ADR 0023: Content federation is contract-bound, signed, and published-only

- Status: Accepted
- Date: 2026-08-24
- Task: M8-002

## Context

GridStory already has canonical serializable schema IR, immutable exact published revisions, explicit complete tenant scope, guarded read-only CMS migration, checksummed logical portability, Ed25519-signed plugin manifests, provider-neutral adapters, validated regional published readers, and optimistic memory/SQLite/PostgreSQL documents. These pieces can identify, validate, and move content, but none lets one scope retain a remote-backed external type without copying every record or syndicate exact published records to another installation with attribution and withdrawal behavior that remains bound to the source contract.

M8-002 has two related but distinct needs. Live federation must resolve an external published type without turning the remote source into a local draft or cache. Syndication must let an operator review and retain a bounded read-only mirror for availability or downstream delivery. Both must prevent scope/schema/revision substitution and must carry source, version, license, credit, and responsible-agent assertions with every record. GridStory cannot claim those assertions are lawful or true; it can make them mandatory, immutable, attributable, and reviewable.

## Prior-art comparison

| Approach | Representative evidence | Fit and cost | Decision / deliberately skipped |
|---|---|---|---|
| Direct remote references with declared source/type targets | Contentful cross-space `ResourceLink`/CRN and Sanity `crossDatasetReference` | Demonstrates that source identity, target types, credentials/permissions, disappearance, depth, and caching behavior must be explicit. It does not provide a portable GridStory source contract or attribution history. | Reuse explicit namespace/type/source pinning and fail-closed missing-target behavior. |
| Adopt JSON Schema as a second external type system | JSON Schema 2020-12 canonical `$id`, `$ref`, and compound documents | Mature external schema identity, but GridStory already has one canonical IR used by validation, Studio, APIs, generation, and migration. A second dialect would create translation and feature-parity obligations. | Rejected for M8-002. Use immutable namespaced GridStory schema IR plus its fingerprint; reconsider mappings in M8-004. |
| ActivityStreams/ActivityPub-style objects and activities | W3C ActivityStreams global IDs, actors, objects, `attributedTo`, publish/update/delete vocabulary | Useful federation vocabulary, but social actors, inbox/outbox delivery, addressing, discovery, and activity semantics exceed the CMS type/tenant/publication contract. | Do not implement protocol conformance; reuse the distinction between object identity and attribution. |
| WebSub hub subscription and callback delivery | W3C WebSub publishers, topics, hubs, leases, callbacks, full/diff notifications, and HMAC delivery | Provides decentralized push distribution, but adds callback SSRF, lease renewal, hub availability, retry, secret, and notification semantics while leaving schema, scope, publication, and rights policy to the application. | Defer push/hub interoperability; use bounded operator-triggered pull in this slice. |

| Reuse migration or logical portability | GridStory M6-004 and existing logical archives | Strong checksums, source links, reconciliation, previews, and retry behavior, but creates ordinary local content, copies every record, and lacks live remote types plus a mandatory traveling attribution contract. | Reuse bounded snapshots, exact preview digests, checkpoints, and reconciliation; keep federation mirrors separate and read-only. |
| Trust a configured HTTPS adapter response without a signed contract | Typical server-side connector | Small, but TLS authenticates transport endpoints rather than an immutable offer/type/revision/attribution record retained across hops and time; it does not detect adapter replay or schema substitution. | Rejected. ## Decision

GridStory will add one complete-scope optimistic content-federation document, private/no-store and disabled by default. A producer offer has immutable versions and allowlists exact canonical GridStory content-schema versions/fingerprints. It declares a stable source instance, an exact source scope, an HTTPS canonical base, and mandatory attribution terms. Enabling an offer requires an injected signing capability; the private signing key never enters shared schemas, persistence, browser code, responses, logs, or ledgers.

A consumer agreement pins one configured source adapter, source instance and complete remote scope, offer ID/version/digest, Ed25519 key identity/public key, allowed namespaced type versions/fingerprints, and either `live` or `mirror` mode. Agreement changes use optimistic versions and require a newly inspected signed offer. Public callers choose only an active local agreement and namespaced record identity; they can never supply an origin, credential, remote scope, key, or arbitrary query.

The first maintained transport is a GridStory HTTPS source adapter at the trusted Node composition edge. Base URLs are credential-free HTTPS without query or fragments; redirects are disabled; continuation and response URLs must remain on the configured origin; method, time, body bytes, record counts, and JSON depth are bounded; credentials remain only in server composition; adapter failures become generic stable errors. Deployments may inject a different source adapter only if it returns the same strict signed envelope. The core independently validates that envelope rather than trusting adapter parsing.

Every canonical envelope binds protocol version, source instance and complete source scope, a consumer-generated request ID, issued/expiry times, offer ID/version/digest, exact type descriptors and fingerprints, complete-snapshot checkpoint or one requested record, source entry/revision/monotonic sequence, record checksum, and mandatory attribution. Attribution includes the canonical source URL, license URL, credit text, one or more bounded attributed agents, and the exact source/type/offer identities. These are source assertions, not legal verification. W3C PROV's separation of derivation and responsible-agent attribution informs the shape; GridStory does not expose an RDF store or claim PROV conformance.

Producer endpoints require a dedicated `federation.consume` action and emit only exact published revisions from offer-allowlisted, first-slice-supported schemas. Drafts, previews, workflow state, credentials, components/code, assets/binaries, and unsupported relations never enter the envelope. Source responses are private/no-store because server credentials and contractual scope are involved.

`live` consumer delivery fetches one exact record with a fresh request ID, validates the signed envelope, schema, scope, offer, type, revision sequence, checksum, time, and attribution, and persists no record. `mirror` synchronization first creates an expiring preview bound to a complete signed source snapshot and exact agreement/offer/type versions. The preview lists create, update, no-op, withdrawal, and blocker effects and has a canonical digest. Execution requires that digest, revalidates current state and source evidence, persists pending state before applying effects, and is idempotent. Mirrored records are a separate read-only federation projection, never ordinary `ContentEntry` drafts or published pointers. A reviewed withdrawal effect tombstones public mirror delivery while retaining bounded receipt and attribution history; it never deletes local content.

Consumer public delivery returns only the namespaced external type, exact data, source revision, and mandatory attribution. It omits complete remote scope, public-key body, adapter identity/configuration, credentials, and raw errors. Live and mirror responses remain no-store in M8-002 because source withdrawal and offer/key changes have no cross-instance cache-invalidation contract yet.

## Necessity gate

1. **Traceable:** M8-002 and the roadmap explicitly require remote-backed external content types and cross-organization syndication with contractual source/version attribution.
2. **Not already solved:** migration and portability copy ordinary local content; regional adapters have no remote type/offer/rights/checkpoint contract; webhooks deliver local events rather than attributable remote published records.
3. **Minimal form:** one offer, one agreement, one maintained safe HTTP adapter, one signed published envelope, live-by-ID resolution, one reviewed mirror loop, and mandatory attribution are the smallest coherent vertical slice. Push hubs, remote edits, scheduling, rich references, assets, search, and public standards are excluded.
4. **Dependencies justified:** no dependency is added. Existing Zod schemas, canonical JSON/checksums, Node Ed25519 verification, complete scope, authorization, repository, and adapter conventions are sufficient.
5. **Rule of three:** this extends established capability-adapter and complete-scope-document patterns rather than adding a provider registry, generic pub/sub system, second schema framework, or protocol toolkit. Only the concrete GridStory HTTP transport is maintained in the first slice.
6. **Reversible:** offers and agreements default disabled, sources and ordinary local content are never mutated, live reads persist nothing, mirrors are isolated projections, and withdrawals are tombstones. Disable all agreements/offers, reconcile or expire plans, export required receipts, then revert the additive commit.

## Sources that changed the decision

- [Contentful cross-space references](https://www.contentful.com/developers/docs/references/content-management-api/cross-space-references/) use explicit resource identities and allowed target resources; its [delivery resource-link limits](https://www.contentful.com/developers/docs/references/content-delivery-api/resource-links/) make credentials, resolution depth, errors, and caching part of the operational contract rather than invisible details.
- [Sanity cross-dataset references](https://www.sanity.io/docs/studio/cross-dataset-references) require the referenced dataset and target types in advance and document permission, missing-target, weak-reference, deletion, and query limitations. GridStory likewise pins source/type identity and makes withdrawal explicit.
- [JSON Schema 2020-12 core](https://json-schema.org/draft/2020-12/json-schema-core) separates canonical schema URI identity from network retrieval and defines stable bundling. GridStory adopts stable namespaced identity, not a second schema dialect or implicit network fetch.
- [W3C PROV-O](https://www.w3.org/TR/prov-o/) distinguishes derivation (`wasDerivedFrom`) from responsibility (`wasAttributedTo`), which motivates separate source-revision and attributed-agent fields.
- [W3C ActivityStreams 2.0](https://www.w3.org/TR/activitystreams-core/) and its [vocabulary](https://www.w3.org/TR/activitystreams-vocabulary/) demonstrate global object identity and attribution but also reveal the much broader social-activity model deliberately excluded here.
- [W3C WebSub](https://www.w3.org/TR/websub/) defines hub subscription, callback delivery, full/diff payloads, and authenticated distribution. Those push/lease/hub responsibilities are deferred until a concrete interoperability need.
- [RFC 9421](https://www.rfc-editor.org/rfc/rfc9421.html) requires an application to define exact signature coverage, algorithms, keys, time, and replay behavior, while [RFC 9530](https://www.rfc-editor.org/rfc/rfc9530.html) covers message content digests. M8-002 avoids a partial HTTP profile and signs the complete canonical application envelope instead.

## Consequences and revisit triggers

- Live types remain coupled to source latency and availability; mirror mode trades freshness for explicit synchronization and retained source revisions. GridStory reports that boundary rather than hiding it behind a generic cache.
- Signed attribution makes source assertions tamper-evident but cannot establish ownership, license validity, required display placement, royalties, or legal permission. Operators must review those matters outside the repository.
- No normal content relation points to a federated record in this slice. Revisit a federated-reference field only after at least three real schemas demonstrate required integrity, fallback, preview, type generation, search, and publication semantics.
- Revisit shared caching only after an invalidation/revocation contract binds offer, agreement, source revision, and withdrawal across installations.
- Revisit push delivery, key rotation/discovery, standardized HTTP signatures, ActivityStreams/WebSub mapping, public schema/archive formats, and third-party provider adapters under M8-004 or another separately approved interoperability task.

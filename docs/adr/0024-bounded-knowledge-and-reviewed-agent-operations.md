# ADR 0024: Knowledge is derived and agent operations are mediated, reviewed draft plans

- Status: Accepted
- Date: 2026-08-24
- Task: M8-003

## Context

GridStory already models typed local relations and taxonomies, validates complete tenant scope, derives backlinks and one-hop related-content reasons, and can re-resolve exact authorized draft or published revisions. It also has a governed AI gateway, reviewed fixed-contract field proposals, private semantic search, capability-limited external plugin runtimes, expiring digest-bound operational plans, human approvals, idempotent receipts, and optimistic memory/SQLite/PostgreSQL documents. Those seams provide most of the safety machinery M8-003 needs, but they do not expose bounded multi-hop graph evidence or let a model choose mediated read tools and propose a later executable operation.

The requested capabilities have different trust levels. Graph exploration and item-to-item recommendations can remain deterministic functions of current authorized content. An agent runtime is untrusted and may be affected by direct or indirect prompt injection, hallucination, excessive agency, stale evidence, or hostile adapter behavior. It therefore must not receive ambient repository access or write-capable callbacks, and model output cannot itself be authority. GridStory must keep normal content authorization, schema validation, immutable draft history, workflow, release, and publication boundaries in control.

## Prior-art comparison

| Approach | Representative evidence | Fit and cost | Decision / deliberately skipped |
|---|---|---|---|
| Materialize an RDF dataset and expose SPARQL | W3C RDF models directed subject-predicate-object statements and named datasets | Expressive and interoperable, but adds a second identity/schema/query surface, entailment and serialization choices, storage synchronization, and public interoperability obligations that current local exploration does not require. | Reject for M8-003. Use repository-native typed nodes, edges, and evidence paths; revisit export/query standards in M8-004. |
| Add a graph database and Cypher/GQL traversal | Neo4j quantified path patterns, predicates, shortest paths, and explicit finite bounds | Mature traversal at large scale, but duplicates authoritative content, adds operational dependencies and consistency/recovery obligations, and still requires application authorization. | Reject until measured corpus/query limits exceed the bounded repository projection. Reuse finite depth, direction, edge-kind filters, cycle handling, and result caps. |
| Reuse current backlinks and related scoring unchanged | GridStory `SearchService` | Zero new persistence and already scope-safe, but only provides direct links, shared taxonomy, same-type weights, and free-form reasons; it has no multi-hop path contract, contribution proof, truncation signal, or agent tool boundary. | Extend the existing derivation semantics into strict graph/recommendation contracts rather than replacing search. |
| Learned or semantic recommendations | Google content-based candidate generation and Amazon Personalize scores/reasons | Useful when user interactions, embeddings, exploration, popularity, or personalization are intended. M8-003 has no user-profile or behavioral-data requirement, and opaque/model-relative scores would weaken complete explanations. | Exclude. Use deterministic relation, taxonomy, type, and bounded-path contributions that exactly sum to the score. |
| Recommendation objects with reviewable state and optimistic fingerprints | Google Cloud Recommender | Separates recommendation evidence from later resource-specific action, uses fingerprints for current-state transitions, and warns that application without review can cause harmful changes. | Reuse immutable evidence, explicit states, stale detection, review, and result receipts for agent plans. |
| Expose a general MCP tool server/client | MCP tools and authorization specifications | Provides a broad ecosystem vocabulary for model-controlled tools, but arbitrary remote tools, OAuth/resource discovery, token handling, dynamic schemas, transport security, and confused-deputy defenses greatly exceed a local fixed CMS operation. | Do not claim MCP conformance. Reuse visible fixed tools, per-call authorization, structured schemas, bounded outputs, and human denial/approval. |
| Reuse the plugin runtime as the agent sandbox | GridStory Plugin SDK v1 | Already has signed manifests, grants, timeouts, and external runtime isolation, but plugin invocation is operator-installed code with declared capabilities, not a model run with a goal, read trace, draft plan, expiry, or human review. | Keep the boundaries separate; agent runtime composition may be externally isolated but receives only the new mediated callback. |
| Let the agent call mutating tools during its loop | Typical autonomous agent loop | Maximizes flexibility but makes prompt injection or one bad decision immediately state-changing and complicates rollback, partial failure, and audit. | Reject. | Derived graph plus deterministic recommendations and a fixed mediated read loop that returns a reviewed draft plan | Selected GridStory boundary | Reuses existing content, AI, authorization, plan, repository, and recovery seams; provides real graph/agent behavior with a small reversible surface. | Selected. |
| Do nothing / retain one-hop related results and non-mutating AI proposals | — | Zero cost, but leaves M8-003's multi-hop exploration and model-directed operation workflow unmet. | Rejected because the queued roadmap requirement is explicit. |

## Decision

GridStory will derive a private, no-store knowledge projection from the authoritative content repository on each request. It will not persist a graph or add a graph database. A query names complete request scope, one perspective, bounded seed entry IDs, direction, edge kinds, content types, and depth. Nodes bind exact current revision identity. Edges are typed relation or taxonomy evidence with their source field/taxonomy path. Breadth-first traversal is cycle-safe and bounded by source entries, depth, nodes, edges, paths, and serialized result bytes. Every content node is re-resolved and authorized before it is returned; a bounded truncation indicator is explicit rather than silently implying completeness.

Recommendations will be item-to-item and deterministic. Candidate contributions come only from direct relation direction, shared taxonomy terms, same content type, and bounded graph paths. Every contribution has a stable rule ID, finite weight, exact evidence, and optional path; the returned total must exactly equal the sum of contributions. Sorting and tie-breaking are stable. No user identity/profile, analytics event, semantic adapter, embedding, model score, popularity, exploration, or hidden signal participates.

One complete-scope optimistic knowledge-agent document will hold disabled-by-default agent policy, bounded plans, human decisions, and execution receipts across memory, SQLite, and PostgreSQL. Policy pins one injected runtime adapter/model, one governed gateway prompt version, allowed draft content types and top-level `text`/`slug` fields, tool-call/result/time/byte limits, and the fixed tool subset. It cannot configure caller URLs, credentials, executable schemas, plugin capabilities, workflow actions, or publication authority.

The agent runtime is a trusted-composition adapter but untrusted output source. GridStory sends only a bounded redacted goal, policy identity, declared fixed tool schemas, and a callback for `content.get`, `graph.explore`, and `recommendation.list`. Each runtime-requested call is strictly parsed, counted, authorized, executed by core, and returned as a bounded projection. Tool calls are read-only. The adapter receives no repository, content service, credentials, network client, plugin runtime, filesystem, shell, workflow, release, or publication capability. A timeout/abort and maximum-call exit are mandatory; invalid or hostile behavior becomes a generic stable error.

The runtime's final output is a strict versioned plan for exactly one existing draft. It may propose multiple changes only to policy-allowlisted top-level text/slug fields, with visible bounded rationale. GridStory independently re-resolves the exact draft revision, applies the proposed changes to a clone, validates the complete deployed content schema and references, and stores an expiring canonical digest over policy/adapter/model/prompt, goal digest, metadata-only tool trace, target revision, changes, and rationale. Raw provider diagnostics, hidden reasoning, raw prompts, full tool results, credentials, or conversation history are never persisted.

Planning, review, and execution use distinct authorization actions. Only a human user principal can approve or reject a pending plan once. Approval does not mutate content. Execution requires the approved digest plus a caller idempotency key, reauthorizes agent execution and ordinary content update, rechecks the current policy/adapter/model/prompt, expiry, target draft revision, allowed field contract, complete resulting schema/references, and review state, and writes pending execution state before calling the existing content update path. Successful retry returns the same receipt. A stale or partially ambiguous result fails closed and requires operator reconciliation; the adapter is never consulted during execution. Execution cannot create/delete entries, edit another entry, change relations/taxonomies/rich text/components/assets, transition or approve workflows, manage releases, or publish.

Private REST routes, typed universal-client methods, and one compact accessible Studio Knowledge panel will cover graph exploration, evidence-bearing recommendations, policy inspection/editing, goal submission, tool trace inspection, plan review, and explicit execution. The panel retains the established neutral page/content/input/border palette and uses existing warning colors. Public delivery and React Server Component/browser entry points remain unchanged.

## Necessity gate

1. **Traceable:** M8-003 explicitly requires knowledge graph exploration, explainable recommendations, and sandboxed agentic operations; earlier AI and readiness work explicitly deferred recommendations and autonomous tools.
2. **Not already solved:** direct related results lack bounded multi-hop paths and exact contribution proofs; semantic search returns candidates only; reviewed AI proposals cannot use model-selected tools or execute; plugins and workflows have no goal/trace/plan/review contract.
3. **Minimal form:** one derived graph, deterministic recommendations, one disabled policy/document, three fixed read tools, one injected runtime, and one human-reviewed single-entry draft patch are the smallest coherent slice. Graph stores, standards protocols, personalization, broad tools, multiple targets, and autonomous publication are excluded.
4. **Dependencies justified:** no dependency is added. Existing Zod, repository scans, reference/taxonomy derivation, AI redaction/gateway prompts, authorization, content validation, canonical checksums, and optimistic persistence are sufficient.
5. **Rule of three:** the service uses established complete-scope document and external adapter patterns but does not create a generic graph backend, tool registry, agent framework, policy language, or protocol abstraction. The three concrete read tools stay explicit.
6. **Reversible:** graph/recommendation state is derived, policy defaults disabled, adapters are injected, planning writes no content, and only a later reviewed ordinary draft update mutates state. Disable policy/adapters, reject or expire plans, retain required receipts, and revert the additive commit; successful drafts remain in normal immutable history.

## Sources that changed the decision

- [W3C RDF 1.2 Concepts](https://www.w3.org/TR/rdf12-concepts/) defines a graph as directed subject-predicate-object triples and separates that structural model from conceptual semantics. GridStory uses typed directed edges without adopting an RDF dataset or syntax.
- [W3C PROV-O](https://www.w3.org/TR/prov-o/) distinguishes derivation and responsible-agent attribution. M8-003 keeps path/tool provenance separate from the human decision and executing actor.
- [Neo4j variable-length paths](https://neo4j.com/docs/cypher-manual/current/patterns/variable-length-paths/) documents exponential path growth and recommends finite upper bounds plus relationship/node predicates. GridStory therefore fixes small depth and cardinality ceilings and explicit edge filters.
- [Google's recommendation overview](https://developers.google.com/machine-learning/recommendation/overview) and [candidate-generation guide](https://developers.google.com/machine-learning/recommendation/overview/candidate-generation) distinguish related-item recommendations and candidate scores while documenting similarity trade-offs. This slice uses transparent content-graph contributions instead of learned embeddings.
- [Amazon Personalize recommendation reasons](https://docs.aws.amazon.com/personalize/latest/dg/recommendations.html) shows reasons can identify promotion, exploration, or popularity rather than explain the entire model score. GridStory requires every deterministic contribution to sum exactly instead of presenting a partial natural-language rationale as a complete explanation.
- [Google Cloud Recommender concepts](https://docs.cloud.google.com/recommender/docs/key-concepts) bind recommendations to current state with an etag and explicit lifecycle; its [API guidance](https://docs.cloud.google.com/recommender/docs/use-api) warns that applying recommendations without impact review can cause harmful changes. GridStory uses an expiring digest, human decision, stale revalidation, and a separate execution receipt.
- [MCP tools](https://modelcontextprotocol.io/specification/draft/server/tools) recommends visible exposed tools and human ability to deny invocations, while the broader [MCP specification](https://modelcontextprotocol.io/specification/2024-11-05/index) treats tools as arbitrary data/code paths requiring consent and authorization. GridStory keeps a much smaller local fixed-tool callback and does not claim protocol conformance.
- [OWASP LLM06:2025 Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) identifies excessive functionality, permissions, and autonomy plus indirect prompt injection as damaging agent failure modes. Read-only planning tools and later host-controlled reviewed mutation minimize all three agency dimensions.
- [OpenAI's practical guide to building agents](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/) recommends starting with one agent, explicit tools and exits, layered guardrails, risk-rated actions, and human intervention for sensitive operations. M8-003 avoids multi-agent orchestration and pauses before every mutation.

## Consequences and revisit triggers

- Repository-derived traversal is intentionally bounded and may report truncation on larger scopes. Revisit a materialized or injected graph adapter only after measured workloads repeatedly exceed the published source-entry/path limits and a consistency/recovery design is approved.
- Deterministic item-to-item recommendations are explainable but not personalized and make no engagement, causal, quality, factuality, safety, or business-outcome claim. Learned or semantic ranking requires a separate data, consent, evaluation, bias, drift, and explanation decision.
- The sandbox is a capability boundary, not a claim that provider code runs inside an OS/container sandbox. Production composition remains responsible for runtime process/container isolation, credentials, egress, retention, billing, regional processing, telemetry, and emergency disablement.
- Revisit relation/taxonomy/rich-content or multi-entry mutations only after at least three concrete workflows establish safe merge, conflict, partial-failure, review, and rollback semantics.
- Revisit MCP interoperability, dynamic tool discovery, remote connectors, long-running/scheduled agents, conversations/memory, multi-agent delegation, or publication actions only through separately approved tasks with protocol, identity, consent, and operational evidence.
